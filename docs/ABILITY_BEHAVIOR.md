# 技能行为、状态生命周期与生命值结算

这批修改以服务端代码和现有技能资源为依据，回归范围如下：

| 问题 | 修正 | 验证 |
| --- | --- | --- |
| 按角色名前缀自动加载全部动态技能，导致普通纳西妲进入 BossRush 特殊模式 | 基础技能仅取显式配置，天赋、命座和活动技能按对应机制启用 | 实际资源基础技能从 19 恢复为 12；命座仅添加对应技能；任务技能定义保留 |
| 重复初始化、重新分配技能 ID 和参数覆盖处理使技能编号或参数丢失 | 按指定位置复用或替换技能，并应用字符串及哈希参数覆盖 | 重复初始化、占用位置重分配、长按伤害初始化及哈希更新 |
| `AddGlobalValue` 未启用限值时仍按默认零上下限截断 | 仅在 `useLimitRange` 为 true 时限值 | 无限值加法、限值加减法 |
| 多个技能线程同时命中丢失计数 | 按计数键原子更新 | 16 个线程各加 100 次，结果为 1600 |
| 队伍伪实体没有场景时加法抛异常 | 无场景时保留计数更新 | 不抛异常且计数正确 |
| `SetGlobalValue` / V2 忽略配置限值 | 两种写入均遵循启用的上下限 | 上下边界、动态参数边界、未启用限值 |
| `LessAndEqual` 被当作等于 | 使用小于等于比较 | 纳西妲标记数 0 至 8，阈值 7 |
| `ApplyModifier` 添加状态时提前执行 `onAttackLanded` | 仅执行添加回调，命中回调留给真实技能调用 | 添加时命中数为 0，实际命中调用后为 1 |
| 带父技能名称或哈希的状态消息重新创建技能，丢失覆盖参数 | 按来源实体和父技能名称复用已有实例，名称与实例索引冲突时以名称匹配 | 名称、哈希、无实例 ID、索引冲突、动态状态复用 |
| 附加到敌人的状态没有被状态条件识别 | 按目标实体记录状态，同时查询客户端实例 | 客户端添加、移除与 `ByHasModifier` 判断 |
| 多个目标或施法者使用同名状态时相互覆盖、移除 | 按目标和来源技能分别记录 | 两个目标分别移除、两个施法者同时附加 |
| 状态替换或到期留下旧名称，或误删新状态 | 替换客户端 ID 时清理旧引用；到期仅移除对应控制器 | 相同 ID 替换、两个实例按不同顺序到期 |
| 非法负数状态索引抛出异常 | 同时检查索引上下界 | 既有状态保留，非法调用被忽略 |
| 状态移除后目标仍保留施法者引用，反复战斗积累空记录 | 最后一个命名状态移除时删除来源记录；动态技能在施法者上按名称缓存 | 客户端移除、主动移除、不同施法者替换、100 个来源依次到期 |
| 清理状态会影响动态技能参数复用 | 动态技能参数与活跃状态分开保存 | 状态到期后再次施放保留覆盖参数 |
| 联机队友及其召唤物被当作敌方目标 | 同世界玩家的角色和召唤物按友方选择 | 敌方排除、友方包含、空来源、最近目标的距离和高度限制 |
| 生命值条件忽略数字阈值及比较逻辑 | 支持数字、技能变量、表达式和资源中使用的大于、小于、等于及包含边界的比较 | 零阈值、无最大生命值、严格边界；班尼特实际 70% 条件 |
| 全局计数条件将技能变量、表达式误读为零 | 与动作共用施法者属性、全局值和技能参数 | 艾尔海森资源中的攻击次数减一条件，变量与属性引用 |
| `AttachModifier` 只筛选第一条生命值条件，使用固定 50% 兜底 | 对每个接收目标逐条判断已支持的条件，普通附加也判断条件 | 数字阈值、状态条件；芙宁娜三种召唤物的实际回调 |
| 治疗和扣血动作忽略自身条件 | 条件通过后执行生命值变化 | 班尼特实际治疗回调；被条件阻止的治疗和扣血 |
| 按目标当前生命值治疗、扣血使用了最大生命值 | 分别使用当前与最大生命值作为计算基数 | 混合基数、扣血下限；芙宁娜实际强化攻击扣血回调 |
| 固定治疗量与百分比组合时固定部分加两次 | 固定部分仅计入一次 | 固定、百分比组合；班尼特实际回调计算 |
| 技能复活对零生命值角色调用普通治疗，始终没有恢复生命值 | 使用独立复活方法，恢复生命值后清除死亡及死亡结算标记 | 芭芭拉满血复活、七七半血复活；复活后再次受伤 |
| 复活通知先于生命值变化，客户端收到死亡状态 | 恢复生命值后发送角色生命值、场景实体生命值及存活状态 | 解析三类实际协议通知，检查值和顺序 |
| 食物、神像和团灭重生仍留下实体死亡标记 | 食物与神像共用复活方法；团灭重生恢复 40% 生命值并清除标记 | 食物路径复活后继续治疗；团灭后继续受伤 |
| 所有复活动作都作用整队，忽略目标范围及自身条件 | 分别处理当前角色、指定角色、整队，并判断动作条件 | 当前角色与指定目标互不影响；条件失败、无效比例不复活 |
| 7.1 资源中的三种生命值比例混淆字段未映射 | 补齐施法者最大生命值、目标当前及最大生命值字段别名 | 七七原始资源与三种比例组合治疗；字段对应由资源中的明文与混淆值配对核对 |
| 复活比例表达式读不到施法者全局值 | 与其他动作共用施法者属性、全局值和技能参数 | 哥伦比娅实际复活动作按友情全局值计算，保持其他角色死亡 |
| 治疗偿还生命之契的变化量符号为正，恢复生命值的原因却为扣血 | 生命之契减少使用负变化量，恢复生命值使用 `CHANGE_HP_ADD_ABILITY` | 解析部分偿还、偿还完成、正常及静默治疗的实际通知 |
| 负数或非有限治疗量增加生命之契或污染数值 | 无效治疗量不参与结算；不能使用非有限生命值或债务状态结算 | 负数、NaN、正负无穷不改变生命值和生命之契 |
| 生命值暂时高于当前上限、且存在生命之契时，接受治疗反而扣血 | 可恢复量最小为零，偿还独立于生命值是否已满 | 满血和超上限生命值均可偿还，超上限治疗不扣血 |
| 同一实体同时接受多个治疗时丢失数值或重复偿还债务 | 同一实体的治疗结算依次完成，在通知前写入生命值和剩余生命之契 | 8 个线程各治疗 100 次；总治疗 4000，偿还 200，实际恢复 3800 |
| 治疗缺少给角色所有者的最终生命值更新 | 实际恢复生命值后发送角色属性通知，并使用实际恢复量发送变化原因 | 溢出治疗只通知实际恢复量；所有者收到封顶后的生命值 |
| 普通治疗兼任死亡标记修复，隐式绕过复活入口 | 普通治疗仅作用于存活角色，复活使用独立入口 | 死亡标记仍在、但生命值被单独写入时，治疗不能复活 |

状态添加回调按配置顺序执行，避免前一动作尚未写入状态时，后一动作已经读取它。

测试：`AbilityActionBehaviorTest`、`AbilityValueTest`、`NahidaSkillStateTest`、`NahidaAbilityInitializationTest`、`NahidaAbilityEmbryoTest`、`AbilityStateLifecycleTest`、`AbilityTargetSelectorTest`、`AbilityPredicateTest`、`AbilityHealthCostTest`、`AbilityHealingTest`、`AbilityRevivalTest`、`HealthSettlementTest`，共 116 项。
它们验证服务端动作与消息处理；具体角色的动画、伤害和多人表现仍应结合客户端实测。

选敌修正覆盖玩家角色与玩家创建的召唤物；非玩家阵营仍沿用原有判断，其余选择器类型没有扩展。
芙宁娜、艾尔海森回归使用资源回调和显式覆盖参数，验证参数参与计算及条件筛选；它们不证明客户端参数初始化与完整角色玩法。
复活回归验证服务端状态、范围、比例和通知；神像使用与食物相同的复活入口，自动复活完整交互、角色天赋冷却及联机表现仍需客户端实测。
生命之契偿还回归同时经过班尼特实际资源回调：显式覆盖治疗参数为 50，债务 20 时实际恢复 30；债务 60 时只偿还 50，不发送恢复生命值事件。完整角色的生命之契添加、转换治疗、已偿还数值读取及触发回调仍需分别核对。
尚未识别的混淆条件仍沿用原有处理，本批没有宣称全部技能条件均已支持。
